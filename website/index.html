CodeMedic

Self-healing coding agents for unattended LLM pipelines

When a scheduled job breaks and nobody is watching, CodeMedic reads the failure from its logs, sends a headless coding agent into the project to find the cause and fix it, and keeps the fix only if the project's own tests still pass.

Agents that run on a schedule fail in ways their authors can't watch for: a site changes its markup, an API changes its shape, a network drop leaves work half done. Usually the fix is small, and the cost is the hours before anyone notices. CodeMedic is an on-call engineer for those agents. It watches their logs, turns new failures into incidents, and starts a headless Claude Code session inside the failing project with the incident, the project's state and a strict set of rules.

The session decides whether the failure is transient, a bug, or something only the author can fix. For a bug, it fixes the root cause, adds a test, commits, and re-runs the step that was stuck. CodeMedic then checks the work itself: it re-runs the tests, reverts the session's commits if they broke anything, and otherwise pushes them and sends the author one message with a one-line undo.

How CodeMedic works

CodeMedic runs every ten minutes and does at most one session per run. Everything it needs from a project is in a few lines of configuration: its repository, its logs, its test command, its lock file, the files a session must never touch, and a note on what the project does.

  1. Step 01

    Watch

    Read only what each log gained since the last look. Failure lines and Python tracebacks become incidents, keyed by a signature with ids, numbers, URLs and paths removed, so one bug on many items is one incident. Errors that usually clear up on their own wait until they repeat.

  2. Step 02

    Heal

    Take the project's tick lock so its own runs wait, run its tests, and start claude -p in the project with a guard hook and a budget. The session classifies the failure, fixes the root cause with the smallest change, adds a test, commits explicit paths and re-runs the stuck step.

  3. Step 03

    Verify

    Re-run the tests. If the session's commits broke tests that passed before, revert them; otherwise push. Send one Slack message with the cause, the fix and the git revert line, and keep the prompt, transcript and report in the run directory.

Guard rails

A session runs with nobody watching, so its limits are enforced in code, not only asked for. A Claude Code PreToolUse hook checks every tool call before it runs and denies the ones below, whatever the session was told by the logs, a web page or its own reasoning.

Limits bound the cost of a bad day: two sessions per error per day, after which the error is muted for a day and the author is alerted, three sessions per project and four in all. A session that loses its connection, or hits the usage limit, is deferred and tried again rather than counted as a failure.

Two weeks in use

From 8 to 23 November 2026, CodeMedic watched four of the author's unattended agents. The five fixes were the kind of change the outside world forces on a scraper or a publisher: a reply form that moved behind a collapsed thread, a comment lookup that dropped underscores and asterisks from text like IQ2_XXS, an editor that changed a hyphen to a dash, and a GitHub call whose timeout crashed a run during a network drop.

Limits

The tests are the gate. CodeMedic keeps a fix when the project's tests pass, so a project with weak tests gets a weak check. Sessions are told to add a test with every fix, which strengthens the gate over time but does not replace review: every fix arrives with its undo line for that reason.

The guard is defense in depth, not a sandbox. It matches commands and paths with rules, and a determined process could get around them. Run CodeMedic only on projects you own, under an account with no more access than those projects need.

One machine, one author. These numbers come from one author's four projects over two weeks, not from a benchmark. CodeMedic is built for a person's unattended automations, with a launchd job on macOS and cron elsewhere, not to replace a team's on-call rotation.

Running it

Clone the GitHub repository, copy config.example.toml to config.toml and describe your projects, then try python3 -m codemedic tick --dry-run. It needs Python 3.11+, git and the Claude Code CLI. The test suite runs heal end to end against a fake agent and a local git remote.
